# ระบบรายงานการจัดสรรงบประมาณจังหวัดหนองบัวลำภู พ.ศ. 2570

เว็บไซต์รายงานงบประมาณรายวัน/รายเดือน พร้อมหลังบ้านสำหรับเจ้าหน้าที่และ PDF A4 **หนึ่งหน้า** สร้างด้วย Next.js 16 + Supabase สำหรับโฮสต์บน Vercel

## ทำอะไรได้บ้าง

- หน้าบ้านแบบ Responsive ดูยอดรวม อนุมัติแล้ว จัดสรรแล้ว คงเหลือ กราฟ และรายละเอียดรายโครงการ
- เลือก **รายวัน** = สถานะล่าสุดที่บันทึกไม่เกินวันที่เลือก; **รายเดือน** = สถานะล่าสุดไม่เกินวันสิ้นเดือน (ไม่บวกตัวเลขจากทุกวัน)
- ส่งออก PDF A4 หน้าเดียวโดยกด **ส่งออก PDF (A4)** → **ดาวน์โหลด PDF** (อักษรไทยแสดงจากหน้าเว็บและฝังเป็นภาพความละเอียดสูงใน PDF)
- หลังบ้านล็อกอิน Supabase Auth บันทึกเป็นฉบับร่าง / เผยแพร่, เพิ่มหรือลบโครงการ, ปรับยอด และระบุเอกสารอ้างอิง
- เก็บข้อมูลเป็น snapshot แยกวันที่ พร้อมบันทึกประวัติการแก้ไขใน `budget_audit_log`
- ป้องกันไม่ให้ประชาชนดึงข้อมูลฉบับร่าง: RLS อนุญาตอ่านเฉพาะที่ `published = true`; การแก้ไขใช้ API ตรวจสิทธิ์ admin บนเซิร์ฟเวอร์

## 1. นำขึ้น GitHub

1. แตกไฟล์ ZIP ของโปรเจกต์นี้
2. สร้าง Repository ใหม่ใน GitHub
3. อัปโหลด **เนื้อหาภายในโฟลเดอร์** `nongbualamphu-budget-dashboard` ไปที่ราก Repository (ต้องมี `package.json` ที่ราก)
4. เก็บ `.env.local` และรหัสลับไว้นอก GitHub เสมอ

หรือใช้ Git ตามปกติ:

```bash
git init
git add .
git commit -m "Initial provincial budget dashboard"
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

## 2. เตรียม Supabase (จำเป็นสำหรับหลังบ้านและอัปเดตถาวร)

1. สร้างโปรเจกต์ใหม่ที่ [Supabase](https://supabase.com)
2. เปิด **SQL Editor** แล้วรันไฟล์ `supabase/schema.sql` ทั้งไฟล์เพียงครั้งเดียว
3. ไปที่ **Authentication → Users** เพื่อเพิ่มผู้ใช้เจ้าหน้าที่ (อีเมลและรหัสผ่าน)
4. ใช้ SQL Editor ให้สิทธิ์ผู้ใช้รายนั้น โดยแทน `YOUR_EMAIL@example.com` ด้วยอีเมลจริง:

```sql
insert into public.admin_users(user_id, display_name)
select id, 'เจ้าหน้าที่งบประมาณ' from auth.users
where email = 'YOUR_EMAIL@example.com'
on conflict (user_id) do nothing;
```

5. ไปที่ **Project Settings → API / API Keys** แล้วคัดลอกค่า URL, anon key และ service_role key สำหรับตั้งค่าบน Vercel

**สำคัญ:** `SUPABASE_SERVICE_ROLE_KEY` ต้องเป็นตัวแปรฝั่งเซิร์ฟเวอร์เท่านั้น ห้ามใส่ `NEXT_PUBLIC_` และห้ามคัดลอกไปไว้ในโค้ด GitHub

## 3. Deploy ผ่าน Vercel

1. เข้า [Vercel](https://vercel.com) → **Add New → Project** → Import GitHub Repository ที่อัปโหลดไว้
2. Framework เลือก Next.js (ระบบมักตรวจพบอัตโนมัติ)
3. ใน **Environment Variables** ตั้งค่า 3 ตัวตาม `.env.example`:

| Variable | ค่า |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon/public key |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase service_role (Secret; เซิร์ฟเวอร์เท่านั้น) |

4. กด **Deploy**; หลัง Deploy เปิด `https://ชื่อโปรเจกต์.vercel.app/admin`
5. ล็อกอินด้วยผู้ใช้ที่เพิ่มไว้ แล้วเลือกวันที่ **15 ตุลาคม 2569** (หรือวันที่ต้องการสร้าง snapshot) → **เปิดข้อมูลวันที่เลือก**
6. ระบบจะเสนอ 11 รายการตั้งต้นจากไฟล์ Excel เดิม ตรวจยอดแก้ไขก่อน บันทึกฉบับร่าง แล้วเลือก **เผยแพร่** เมื่อผ่านการตรวจสอบ
7. กลับไปที่ `/` เพื่อตรวจสอบข้อมูลสาธารณะและดาวน์โหลด PDF

เมื่อแก้ไข Environment Variables บน Vercel หลัง Deploy แล้ว ให้ Redeploy เพื่อให้ค่ามีผลกับ Build ใหม่

## 4. การใช้งานประจำวันที่แนะนำ

1. เจ้าหน้าที่เข้า `/admin` และเลือกวันที่บันทึกใหม่
2. กด **เปิดข้อมูลวันที่เลือก** ระบบคัดลอก snapshot ล่าสุดก่อนหน้านั้น (ถ้ายังไม่มีของวันนั้น)
3. แก้ตัวเลขตามเอกสารต้นทาง บันทึกฉบับร่าง และตรวจคำเตือน
4. เมื่อพร้อมเผยแพร่จึงติ๊ก **เผยแพร่** แล้วบันทึก
5. หน้าบ้านดึงเฉพาะฉบับที่เผยแพร่แล้ว เลือกวันที่/เดือนเพื่อดาวน์โหลด PDF

> การเลือกวันในอดีตจะใช้ snapshot ล่าสุดไม่เกินวันนั้น ระบบไม่ได้สมมุติว่ามีการอัปเดตทุกวัน จึงต้องดู “ข้อมูลบันทึกล่าสุด” บนหน้าเว็บและ PDF ด้วย

## 5. ข้อมูลตั้งต้นและข้อควรระวัง

- แหล่งข้อมูลคือ `บช.โครงการงบ 70 ที่ได้รับจัดสรรงวด 1 ข้อมูลวันที่ 07-10-69.xlsx` แผ่น **จัดสรรงวดที่ 1 ใหม่**
- ในแผ่นดังกล่าวมีหมายเหตุว่า **ข้อมูล ณ วันที่ 15 ตุลาคม 2569** ซึ่งไม่ตรงกับวันที่ในชื่อไฟล์
- นำเข้าเฉพาะ **แถวสรุประดับโครงการ/เงินเหลือจ่าย 11 รายการ** เพื่อไม่ให้นับแถวรายละเอียดซ้ำและเพื่อคง PDF 1 หน้า (ยังไม่ได้นำเข้าทุกรายการกิจกรรมย่อย)
- ยอดรวมที่เขียนไว้ในแถว "รวมทั้งสิ้น" ของไฟล์: งบประมาณ 52,744,500 บาท; อนุมัติ 41,858,200 บาท; จัดสรรงวด 1 39,557,500 บาท; ยังไม่อนุมัติ 10,886,300 บาท; ยังไม่จัดสรร 13,187,000 บาท
- **ผลบวกจัดสรรจาก 11 แถวโครงการ = 39,257,500 บาท** ไม่ตรงกับแถวรวมทั้งสิ้น 39,557,500 บาท (ต่างกัน 300,000 บาท) ระบบจะยึดผลรวมจากแถวโครงการสำหรับกราฟ/รายงานชั่วคราว และแจ้งเตือนให้ตรวจสอบกับต้นฉบับก่อนเผยแพร่
- **รายการ 3 และ 8** มียอด `งบประมาณ − อนุมัติแล้ว` ไม่ตรงกับช่อง `ยังไม่อนุมัติ` ตามบรรทัดต้นทาง โปรแกรมจงใจ **ไม่แก้ตัวเลขอัตโนมัติ** และจะเตือนในหลังบ้าน/ไม่ให้เผยแพร่หากยังไม่ตรงกัน ทั้งนี้หลังบ้านมีช่องแยกให้กรอก "ยอดรวมตามบัญชี" เพื่อตรวจสอบยอดรวมอีกชั้นหนึ่ง
- รายงานนี้เป็น **การจัดสรรงบประมาณ** ไม่ใช่การเบิกจ่าย หากต้องการรายงานผลเบิกจ่ายต้องเพิ่มข้อมูลยอดเบิกจ่ายจากแหล่งที่ถูกต้อง
- การสรุปรายเดือนหมายถึงยอด **ณ สิ้นเดือน** ไม่ใช่ยอดรวมตลอดเดือน เพื่อป้องกันการนับงบคงค้างซ้ำ
- ผู้ที่มีลิงก์รายงานสาธารณะสามารถส่งต่อได้ ข้อมูลอ่อนไหวต้องเก็บเฉพาะหลังบ้าน ไม่ควรใส่ในรายการเผยแพร่

## 6. พัฒนาในเครื่อง

ใช้ Node.js 20.9 ขึ้นไป:

```bash
npm install
cp .env.example .env.local
# กรอกค่า Supabase ของคุณใน .env.local
npm run dev
```

เปิด `http://localhost:3000` และ `http://localhost:3000/admin`  
ทดสอบ: `npm test && npm run typecheck && npm run build`

หากยังไม่ได้ตั้งค่า Supabase หน้าเว็บจะเปิด **โหมดตัวอย่างที่มีป้ายเตือน** จาก `data/seed.json` หลังบ้านจะไม่สามารถบันทึกได้ จึงควรตั้งค่า Supabase ก่อนใช้งานจริง

หากภายหลังมีไฟล์ Excel บัญชีจัดสรรในโครงสร้างเดิม สามารถสร้าง seed ใหม่บนเครื่องนักพัฒนาได้:

```bash
python -m pip install openpyxl
python scripts/build_seed.py "/path/to/new-workbook.xlsx"
```

สคริปต์นี้แทนที่เฉพาะ `data/seed.json` **ไม่อัปเดตข้อมูลที่เผยแพร่ในฐานข้อมูลโดยอัตโนมัติ** เพราะการอัปเดตจริงต้องตรวจสอบและบันทึกผ่านหลังบ้าน

## โครงสร้างสำคัญ

- `app/page.tsx` — หน้าบ้าน
- `app/admin/page.tsx` — หลังบ้าน
- `app/api/report/route.ts` — ข้อมูลสาธารณะ (เฉพาะ snapshot ที่เผยแพร่)
- `app/api/admin/snapshot/route.ts` — API แก้ไขและบันทึกพร้อมตรวจสิทธิ์
- `components/ReportSheet.tsx` — แบบฟอร์ม A4 หน้าเดียว
- `components/PdfPreview.tsx` — ส่งออก PDF
- `data/seed.json` — ข้อมูลตัวอย่างเริ่มต้นจากไฟล์ที่แนบ
- `supabase/schema.sql` — ตาราง, RLS และฟังก์ชันบันทึกแบบ atomic

ฟอนต์ PDF ใช้ Noto Sans Thai (SIL Open Font License 1.1) ที่บรรจุไว้ใน `public/fonts/` เพื่อให้ตัวอักษรไทยพร้อมใช้งาน
