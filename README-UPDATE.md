# อัปเดตเว็บไซต์รายงานงบประมาณจังหวัดหนองบัวลำภู 2570

## สำคัญ — ZIP นี้เป็นไฟล์ **อัปเดตทับ Repository เดิม** ไม่ใช่โปรเจกต์ Next.js แบบแยกเดี่ยว

ห้ามลบไฟล์เดิมออกจาก GitHub ก่อนอัปโหลด เพราะอัปเดตนี้อาศัย `package.json`, `lib/supabase.ts`, `components/Dashboard.tsx`, `app/globals.css` และไฟล์อื่น ๆ ที่อยู่ใน Repository ปัจจุบัน

## การอัปโหลด GitHub

1. ดาวน์โหลดและแตก ZIP บนเครื่องคอมพิวเตอร์
2. เปิด Repository `nongbualamphuannualreport/NongBuaLamphu-Budget-Dashboard`
3. แนะนำให้สร้าง Branch ใหม่สำหรับทดสอบ แล้วนำ **เนื้อหาภายใน ZIP** ไปวางทับในโฟลเดอร์ Repository เดิม (รักษาโครงสร้าง app/, components/, lib/, data/, supabase/)
4. Commit และ Push; เมื่อ Vercel สร้าง Preview Deployment แล้ว ตรวจหน้าเว็บก่อน Merge เข้าสู่ main
5. **รัน `supabase/disbursement.sql` ใน SQL Editor ของ Supabase โปรเจกต์เดิม** (ครั้งเดียว)
6. ไม่จำเป็นต้องเพิ่ม Environment Variables — ใช้ 3 ตัวที่ตั้งค่าไว้แล้ว

### กรณีอัปโหลดผ่านเว็บ GitHub

เปิด Repository → Add file → Upload files แล้วลากโฟลเดอร์/ไฟล์จากการแตก ZIP ให้คงตำแหน่งเดิม ตรวจดูรายชื่อไฟล์ที่จะแก้ก่อน Commit; อย่าอัปโหลด ZIP เป็นไฟล์เดียว เพราะ GitHub/Vercel จะไม่แตก ZIP ให้โดยอัตโนมัติ

## หลัง Deploy

- `/` = Dashboard **ผลการเบิกจ่าย** (ใหม่)
- `/allocation` = Dashboard **การจัดสรร** (เดิม ไม่เปลี่ยนแปลงข้อมูล)
- `/admin` = หลังบ้านจัดสรรเดิม
- `/admin/disbursement` = หลังบ้านผลเบิกจ่ายใหม่ (ใช้ Supabase Auth/Admin เดิม)

ใน `/admin/disbursement` เข้าสู่ระบบ → กด **โหลดข้อมูลล่าสุด 10 พ.ย. 2569 ที่แนบในโปรเจกต์** → ตรวจยอด → **บันทึกฉบับร่าง** → เมื่อพร้อมจึงติ๊กเผยแพร่และกด **บันทึกและเผยแพร่**. ข้อมูลในไฟล์ ZIP ไม่ได้เผยแพร่เองอัตโนมัติ

หากครั้งถัดไปมีไฟล์ Excel ใหม่ ต้องแปลงเป็น JSON ตามโครงสร้าง `data/disbursement-2026-11-10.json` ก่อนนำเข้าทางหลังบ้าน รุ่นนี้ **ยังไม่รองรับอัปโหลด XLSX ตรง ๆ** และไม่มีการอ้างว่าสามารถทำได้

## การตรวจสอบตัวเลข

ข้อมูลล่าสุด ณ 10 พฤศจิกายน 2569:
- งบประมาณรวม 52,744,500 บาท
- เบิกจ่ายแล้ว 833,463 บาท
- คงเหลือ 51,911,037 บาท
- 10 โครงการ + เงินเหลือจ่ายอีก 1 แถว
- รายละเอียดกิจกรรม 35 แถว (ห้ามนำผลรวมกิจกรรมไปบวกยอดโครงการซ้ำ)

โครงสร้างนี้ **แยก** จาก `budget_snapshots` ที่มีปัญหายอดจัดสรรต่างกัน 300,000 บาท และไม่ได้แก้ตัวเลขจัดสรรเดิม

## ความปลอดภัย

ข้อมูลเผยแพร่ผ่าน `/api/disbursement` ซึ่งอ่านเฉพาะ `published = true`; การบันทึกต้องล็อกอินและอยู่ใน `admin_users` ของ Supabase เดิม. ห้ามเปิดเผย `SUPABASE_SERVICE_ROLE_KEY`. ผู้ใช้ควรตรวจไฟล์และยอดกับเอกสารต้นทางก่อนเผยแพร่
